# Convex backend

Backend for W-AI: a multi-tenant website platform where each site gets a managed
tenant hostname plus optional customer-owned domains.

## Customer-owned domains

Domain registration and availability search are deliberately outside the current
product scope. The active lifecycle is BYOD: an admin assigns an owned hostname,
W-AI attaches it to the platform Vercel project, shows the exact A/CNAME and TXT
records, verifies ownership and routing, and only then exposes it to tenant lookup.
The per-host ownership TXT value contains 128 bits of cryptographic entropy; it
is not derived from a user, workspace, hostname, timestamp, or `Math.random`.
Verified hostnames can either serve the assigned site or permanently redirect to
another verified hostname on that same site. Vercel/TLS credentials remain server
side and are never requested from a workspace member.

Each site also owns indexed path redirect rules in `redirectRules`. Rules may
apply to every hostname or one verified custom hostname, use temporary 307 or
permanent 308 semantics, and optionally preserve the incoming query string. The
tenant server resolves these rules before rendering a page. Exact rules take
priority; prefix rules can move a whole section (for example `/blog/*` to
`/journal/:splat`) and choose the longest matching prefix. Mutations reject
duplicate source scopes, unsafe external protocols, unverified hostname scopes,
redirect-only hostname scopes, direct self-redirects, and bounded redirect
cycles. Loop validation follows same-site absolute URLs across the tenant host
and every serving custom hostname, so changing hosts cannot conceal a cycle.
Turning a disabled rule back on repeats hostname and loop validation against the
current rule graph. Runtime lookup uses exact indexed scope queries and indexed
ancestor-prefix queries rather than capped table scans, so valid rules are not
silently skipped when a site has many domains or hundreds of redirects.
Tenant rendering and redirect lookup are host-bound: the internal `/c/[slug]`
rewrite target never grants access by slug alone, and direct requests to that
namespace on the application host are rejected.

Domain purchase, availability search, registrar charging, transfers, renewals,
and redemption are intentionally deferred to a later registration phase. No
registrar order or payment method is required for the current BYOD and redirect
lifecycle.

The future registration ledger is defined in `domainOrders.ts` and is dormant by
design: public clients can read owner-scoped history and see that purchasing is
disabled, while all payment/provider transitions are internal. See
`docs/domain-registration-lifecycle.md` for the Openprovider + Dodo + Vercel
money and fulfillment model.

## Structure

- `schema.ts` — global data model (organizations, pages, properties, chat, …).
  Auth tables (users, sessions, accounts) live in the better-auth component.
- `auth.ts` / `auth.config.ts` / `http.ts` — better-auth wiring exposed through
  the Convex auth provider (`/api/auth`).
- `helpers.ts` — shared guards (`requireOrgAccess`, `requireAdmin`, …).

## Commands

```bash
npx convex dev        # local dev server + codegen
npx convex deploy     # deploy to configured project
npx convex dashboard  # open the Convex dashboard
```

`convex/_generated/` is generated by codegen and committed to the repo.
